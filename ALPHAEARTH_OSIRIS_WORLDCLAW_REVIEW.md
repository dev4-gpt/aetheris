# AlphaEarth, OSIRIS, and WorldClaw for Aetheris

**Checked 23 October 2026.** These sources solve different problems. Google AlphaEarth provides annual geospatial **embeddings** for analysis; OSIRIS is an MIT-licensed **dashboard codebase** that aggregates third-party feeds; WorldClaw currently publishes a **research method**, not reusable software. None is a verified live world model or a substitute for permissioned observations and user validation.

## AlphaEarth: real integration boundary

The [Google catalog](https://developers.google.com/earth-engine/datasets/catalog/GOOGLE_SATELLITE_EMBEDDING_V1_ANNUAL) says each 10 m pixel stores a 64-dimensional vector summarizing **one calendar year**, with bands `A00`–`A63` in local UTM projection. The bands are learned features; they are not standalone physical measurements. Google documents annual embeddings through 2025 in its [GCS guide](https://developers.google.com/earth-engine/guides/aef_on_gcs_readme), including attribution and provider-paid bucket access as of July 2026. Earth Engine access requires an enabled Cloud project; [commercial startup use requires a paid configuration](https://developers.google.com/earth-engine/guides/transition_to_commercial). Dataset rights and platform charges are distinct.

The current `gods-eye-view/src/modules/alphaEarthCartridge.js` instead creates a coordinate-seeded vector and derives arbitrary flood, fire, soil, crop, and anomaly numbers. It has **never sampled the Google dataset**. This review changes the visible prototype to label those values synthetic and removes claims of measured SAR, ground truth, and operational advice. The old command names remain for compatibility, not as a source claim.

**First real experiment:** select one permitted, non-sensitive pilot area and two annual embedding vintages. In a backend/offline job, fetch only the necessary COG windows or use a commercial Earth Engine project; record asset URI, dataset/model version, year, CRS, processing code hash, attribution, and any cost. Compute a clearly labeled similarity/change layer from the full 64-vector; compare against a rights-cleared reference dataset and held-out locations. Display annual age and uncertainty. Do not emit hazard percentages without labeled data, calibrated models, and evaluation. Put the adapter behind the planned `packages/observation-contract/` and render it as an **inference layer**, separate from observations.

## OSIRIS: code rights differ from feed rights

OSIRIS documents [Next.js API routes, MapLibre layers, and lazy viewport-aware fetching](https://github.com/simplifaisoul/osiris#architecture). Its [MIT license](https://github.com/simplifaisoul/osiris/blob/master/LICENSE) permits code adaptation with notices, but each feed has separate terms. For example, [OpenSky requires a written license for commercial entities and operational REST use](https://opensky-network.org/about/terms-of-use). Public CCTV URLs may have operator-specific redistribution, privacy, reliability, or access conditions. The OSIRIS README itself distinguishes static maritime port/chokepoint data from live tracks and says Texas CCTV is refreshing JPEG snapshots, not video. A map marker is not proof of a live sensor.

**First OSIRIS-inspired experiment:** implement one source-neutral layer manifest in the existing app: ID, source URL, license/permission record, observed and fetched times, refresh interval, geometry type, status (`live`, `delayed`, `static`, `synthetic`, `unavailable`), and attribution. Start with a saved fixture and one source whose terms explicitly permit the intended use. Test stale data, rate limits, failed fetches, keyboard access, and exported provenance. Reuse a small reviewed OSIRIS component only if it saves more than an adapter implementation and its transitive rights are checked. Avoid importing the entire app or consuming its hosted service as an undocumented API.

## What to build first

1. Finish the master plan's **honest-demo** gate: no source badge or risk number should imply observed data when it comes from fixtures.
2. Ship one replayable permitted observation adapter with provenance and an operator task benchmark. This is the startup wedge.
3. Trial an AlphaEarth annual-change layer for a defined planning question, budgeted access, and validation set. Keep it distinct from the live observation layer.
4. Trial a licensed synthetic 3D scene only if an operator study shows it improves the same task. WorldClaw remains research input until software and terms are published.

These integrations can improve the product, but their presence alone cannot establish situational accuracy, defense readiness, interoperability certification, or funding eligibility.
